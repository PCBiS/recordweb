# recordWEB v1.3.0 Docker

recordWEB v1.3.0을 Linux Headless 모드로 실행하는 컨테이너 이미지입니다. 치지직·씨미 라이브를 녹화합니다.

원본 배포 ZIP(`upstream/recordWEB_v1.3.0.zip`)을 그대로 풀어 넣고, 컨테이너에서 접속하는 데 필요한 패치 하나만 적용했습니다. 기능은 원본과 같습니다. 사용법은 ZIP 안의 `README.md`를 보세요.

## 원본과 다른 점

| 항목 | 내용 |
|---|---|
| 실행 | `recordWEB.sh` 대신 백엔드를 바로 실행합니다. 창과 트레이는 없습니다 |
| 패치 | 4건. 아래 "패치" 참고. 내용은 `patches/apply.py`에 있습니다 |
| 첫 실행 설정 | 설정 파일이 없으면 원본 기본값을 복사하고 **다른 기기에서 접속 허용**을 켭니다. 그 밖의 값은 원본 기본값입니다(로그인 꺼짐) |
| 다시보기 | 원본에서 별도 Windows 프로그램(`replayDownloader`)으로 제공합니다. 이 이미지에는 없습니다 |
| GPU 인코딩 | 시험하지 않았습니다 |

## 시작 (Linux, 호스트 망)

```sh
mkdir recordings && sudo chown 10001:10001 recordings
docker compose up -d
```

`compose.yaml`은 `network_mode: host`를 씁니다. 원본을 서버에 직접 설치한 것과 같게 동작합니다.

| 접속 | 주소 | 할 수 있는 일 |
|---|---|---|
| 서버 PC에서 | `http://127.0.0.1:5000` | 전부. 쿠키 저장, 계정 만들기, 새 저장 폴더의 채널 추가, 알림 토큰, 파일매니저·FFmpeg 설정은 여기서만 됩니다 |
| 다른 기기에서 | `http://<서버 IP>:5000` | 녹화 시작·중지, 기존 저장 폴더를 쓰는 채널 추가·수정, 일반 설정 |

- 화면이 없는 서버라면 SSH 터널로 서버 PC 접속을 대신합니다: `ssh -L 5000:127.0.0.1:5000 <서버>` 후 내 PC에서 `http://127.0.0.1:5000`.
- 채널의 저장 폴더는 `/app/output` 아래로 지정하세요.
- 이 구분은 원본 v1.3.0의 정책입니다("서버 PC에서 변경하세요"라는 안내가 나옵니다).

## 접속 주소 (`RWEB_ALLOWED_HOSTS`)

recordWEB v1.3.0은 요청의 주소(Host 헤더)가 `127.0.0.1`·`localhost`이거나 서버 자신의 IP일 때만 받습니다. 그 밖의 주소로 접속하면 `허용되지 않는 접속 주소입니다`(400)가 나옵니다. 리버스 프록시의 이름이나 bridge 망의 호스트 주소로 접속하려면 그 주소를 `RWEB_ALLOWED_HOSTS`에 적습니다. 이 이미지가 원본에 더한 유일한 패치입니다.

| 접속 방법 | `RWEB_ALLOWED_HOSTS` |
|---|---|
| 호스트 망, `http://<서버 IP>:5000` | 필요 없음 |
| 리버스 프록시 `https://rec.example.com` | `rec.example.com` |
| bridge 망, `http://192.168.0.10:5000` | `192.168.0.10:5000` |
| bridge 망, 포트를 `8080:5000`으로 게시 | `192.168.0.10:8080` |
| 여러 개 | `192.168.0.10:5000,rec.example.com` |

- 브라우저 주소창의 주소와 글자 그대로 같아야 합니다. 포트가 80·443이 아니면 포트까지 적습니다.
- 리버스 프록시는 원래의 `Host` 헤더를 그대로 넘겨야 합니다(nginx: `proxy_set_header Host $host;`).
- 비워 두면 원본과 똑같이 동작합니다.
- 이 목록의 주소로 들어온 접속은 프록시가 같은 서버에 있어도 "다른 기기"로 취급합니다. 서버 PC 전용 기능은 열리지 않습니다.

## bridge 망으로 실행

`compose.bridge.yaml`은 포트를 게시하는 일반적인 구성입니다. 호스트 망을 쓸 수 없을 때(Docker Desktop 등) 씁니다.

bridge 망에서는 게시한 포트로 들어온 접속이 모두 "다른 기기"입니다. 서버 PC 전용 기능은 **관리 포트**로 씁니다.

| 접속 | 주소 | 할 수 있는 일 |
|---|---|---|
| 관리 포트 (서버 PC에서) | `http://127.0.0.1:5001` | 전부 |
| 다른 기기에서 | `http://<서버 IP>:5000` (`RWEB_ALLOWED_HOSTS`에 적은 주소) | 녹화 시작·중지, 기존 저장 폴더를 쓰는 채널 추가·수정, 일반 설정 |

- 첫 채널, 쿠키, 알림 토큰은 관리 포트에서 넣으세요. 기본 채널 목록이 비어 있어 다른 기기에서는 첫 채널을 추가할 수 없습니다.
- 관리 포트는 `RWEB_ADMIN_PORT`를 줄 때만 열립니다. **호스트의 `127.0.0.1`에만 게시하세요**(`127.0.0.1:5001:5001`). 다른 주소에 게시하면 그 망의 누구나 관리자가 됩니다. 같은 Docker 망의 다른 컨테이너도 이 포트에 닿을 수 있으므로 전용 망에서 쓰세요.
- 게시하는 호스트 포트와 `RWEB_ADMIN_PORT`는 같은 번호여야 합니다.
- 화면이 없는 서버라면 SSH 터널을 씁니다: `ssh -L 5001:127.0.0.1:5001 <서버>`.

## 보안

- **로그인 없이 누구나 녹화 시작·중지, 채널 추가·삭제, 일반 설정 변경을 할 수 있습니다.** 원본 v1.3.0의 동작입니다. 계정 로그인은 파일매니저와 계정 변경에만 쓰이고, 설정 파일의 `loginMode` 값은 접근을 막지 않습니다.
- 신뢰할 수 있는 내부망에서만 쓰고 인터넷에 직접 공개하지 마세요. 밖에서 쓰려면 인증이 있는 리버스 프록시나 VPN 뒤에 두세요.
- 리버스 프록시가 `Host: localhost:5000`처럼 loopback 주소로 넘기면 모든 사용자가 "서버 PC"로 취급됩니다. 프록시는 원래의 `Host`를 넘기게 하고 그 이름을 `RWEB_ALLOWED_HOSTS`에 적으세요.
- **다른 기기에서 접속 허용**과 서버 포트는 서버 PC(또는 관리 포트)에서만 바꿀 수 있습니다(이 이미지의 패치).
- 쿠키와 알림 토큰은 `/app/json` 볼륨에 평문으로 저장됩니다(`.bak` 사본 포함). 이 볼륨을 백업하거나 공유할 때 주의하세요.

## 볼륨과 설정

| 경로 | 내용 |
|---|---|
| `/app/json` | 설정, 채널, 쿠키, 계정, 후처리 기록. 반드시 보존하세요 |
| `/app/logs` | 백엔드 로그. 기본 보관 기간은 3일입니다 |
| `/app/output` | 녹화 파일의 기본 위치 |

| 환경변수 | 기본값 | 내용 |
|---|---|---|
| `RWEB_ALLOWED_HOSTS` | 없음 | 추가로 허용할 접속 주소. 쉼표로 구분 |
| `RWEB_REMOTE_ACCESS` | `true` | `false`면 첫 실행 때 **다른 기기에서 접속 허용**을 켜지 않습니다(원본 기본값. 서버 PC에서만 접속) |
| `RWEB_ADMIN_PORT` | 없음 | bridge 망용 관리 포트(1024~65535). recordWEB 포트와 달라야 합니다 |
| `TZ` | `Asia/Seoul` | 시간대 |

- 컨테이너는 UID·GID `10001`로 실행합니다. 호스트 폴더를 연결하면 소유자를 맞추세요.
- 포트는 `json/config.json`의 `port`입니다(기본 5000). bridge 망에서는 게시 포트만 바꾸면 됩니다(`8080:5000`).
- 실행 중에는 `json/dependency_usage.json`이 2초마다 다시 쓰입니다.

## 녹화 중에 컨테이너를 멈출 때

녹화 중에 컨테이너를 멈추거나 다시 만들면 녹화는 바로 끊기고, 그 파일은 후처리(시간 정보 정리)를 거치지 못한 채 남습니다. 내용은 남아 있지만 재생 길이가 틀리게 보일 수 있고, 다시 시작해도 자동으로 후처리되지 않습니다. 먼저 화면에서 녹화를 중지하고 후처리가 끝난 뒤에 멈추세요. 이미 끊긴 파일은 다음처럼 직접 정리할 수 있습니다.

```sh
docker exec recordweb ffmpeg -fflags +genpts -i "/app/output/<파일>.mp4" -c copy -movflags +faststart "/app/output/fixed_<파일>.mp4"
```

## 패치

원본 파일은 아래 4곳만 바꿉니다. 환경변수를 주지 않으면 1·2는 원본과 같게 동작합니다.

| 번호 | 구분 | 내용 | 파일 |
|---|---|---|---|
| 1 | 컨테이너 맞춤 | `RWEB_ALLOWED_HOSTS`의 주소를 접속 주소와 Origin 검사에서 허용 | `module/access_control.py`, `module/recordWEB.py` |
| 2 | 컨테이너 맞춤 | `RWEB_ADMIN_PORT`로 온 loopback 주소 요청을 서버 PC 주소로 인정 | `module/access_control.py` |
| 3 | 보안 | 다른 기기에서 **다른 기기에서 접속 허용**과 서버 포트를 바꿀 수 없게 함. 원본은 누구나 요청 한 번으로 원격 접속을 꺼서 모두를 잠글 수 있습니다 | `module/recordWEB.py` |
| 4 | 보안 | 씨미 요청이 인증서 검증에 실패했을 때 검증 없이 다시 요청하던 동작 제거 | `module/cime_recorder.py` |

## 직접 빌드

```sh
docker build -t recordweb:1.3.0 .
```

빌드는 ZIP의 SHA-256과 패치 대상 파일의 SHA-256을 확인합니다. 다른 ZIP으로 바꾸면 빌드가 실패합니다.

| 구성 | 버전 |
|---|---|
| Python | 3.13 (`python:3.13-slim-bookworm`) |
| Python 패키지 | 원본 `module/install/requirements-linux.txt` 그대로 (Streamlink 8.6.3 등) |
| FFmpeg | Debian 12 패키지 |
